# Research Sources

Research checked on 2026-10-14. Standards, laws, and project pages can change; verify the current version and applicability when writing a real specification.

## Requirements and SDLC

- **ISO/IEC/IEEE 29148:2018, Systems and software engineering — Life cycle processes — Requirements engineering.** The ISO page describes requirements processes across the life cycle, the information items produced, and their required content/format. ISO lists the 2018 edition as current and indicates a successor draft is in development. The full standard is paywalled, so this skill uses the public abstract only and does not claim conformance.  
  https://www.iso.org/standard/72089.html
- **NIST SP 800-218, Secure Software Development Framework (SSDF) v1.1.** NIST explains that security practices should be integrated into the chosen SDLC; the framework organizes practices around preparing the organization, protecting software, producing well-secured software, and responding to vulnerabilities. Use it as a secure-development reference, not as a universal product-spec template.  
  https://csrc.nist.gov/pubs/sp/800/218/final

## Architecture

- **arc42 overview and template.** A practical, adaptable structure covering goals/constraints, context, solution strategy, building blocks, runtime/deployment views, decisions, quality requirements, risks, and glossary. The feature-spec workflow uses only relevant sections.  
  https://arc42.org/overview

## Security Verification

- **OWASP Application Security Verification Standard (ASVS), version 5.0.0.** OWASP describes ASVS as a basis for testing application security controls and secure-development requirements. OWASP recommends version-qualified requirement IDs because identifiers may change; the skill therefore asks specifications to record the exact edition/source used.  
  https://owasp.org/www-project-application-security-verification-standard/
  https://github.com/OWASP/ASVS/tree/v5.0.0

## Interpretation

These sources inform the workflow but do not establish which laws, standards, or internal policies apply to this application. Applicability depends on product behavior, data, users, deployment, contractual context, and jurisdiction. The skill asks the author to record that analysis and seek qualified review where interpretation is required.
